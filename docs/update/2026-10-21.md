## 图片预览改为 WebView URI 访问

### 需求描述
导入图片和重命名图片的预览不再将图片转换为 Base64 内嵌到页面，而是把工作区（以及外部图片目录）加入 WebView 的 `localResourceRoots`，通过 `webview.asWebviewUri` 生成资源 URI 直接访问图片。

### 效率评估
- **Base64**：需要在扩展宿主中同步读取整张图片并编码，体积膨胀约 33%；导入/重命名的冲突预览在每次输入触发冲突检测时都会重新读取并编码冲突图片；大图或多图场景下扩展宿主 CPU、内存和 WebView 消息体积开销明显。
- **WebView URI**：仅生成短 URI，由 WebView 通过 VS Code 资源协议按需加载，浏览器可缓存和复用；冲突检测只传递 URI，不再重复读取图片文件。大图场景优势明显，小图额外的一次资源请求开销可忽略。
- **结论**：改用 URI 访问。

### 实现细节
- `ImagePreviewUtils` 改为提供 `toWebviewUri(webview, filePath)`。
- 导入预览的 `localResourceRoots` 包含 `sdk.workspace` 和所有待导入的密度目录（支持外部目录与 ZIP 解压临时目录）；重命名预览包含 `sdk.workspace` 和所有图片基础目录（支持工作区外的图片）。
- 预览字段由 `previewData`（Base64）改为 `previewUri`，冲突预览同样改为 URI。
- 预览 URI 在 WebView 创建后生成，确保 `asWebviewUri` 的转换在有效 WebView 上下文中执行。

- `src/utils/image-preview-utils.ts` (修改)
- `src/command/import-android-images.ts` (修改)
- `src/command/rename-image-variants.ts` (修改)

## 重命名图片支持多选并使用列表预览 UI

### 需求描述
重命名图片及所有变体时，参照「导入 Android 图片资源」的预览 UI 展示待重命名的图片列表；支持在资源管理器中一次选中多张图片分别重命名。重命名时只要存在冲突（批次内同名或目标目录已存在同名文件），就不允许执行重命名，冲突提示统一为「已存在同名文件」。

### 实现细节
- **命令入口**：`flutterDevTools.renameImageWithVariants` 的命令回调改为接收 `(uri, uris)`，支持资源管理器多选；非图片文件会被自动过滤。
- **图片分组**：复用 `ImageVariantUtils.collectVariants`，按「基础目录 + 文件名」去重分组，每组包含基础图片及其在 `1.5x`/`2.0x`/`3.0x`/`4.0x` 等变体目录下的同名文件。
- **列表预览 UI**：使用 WebView 展示与导入预览一致的列表，每行包含图片缩略图和完整文件名输入框，底部固定「取消」「确认重命名」按钮。
- **实时冲突检测**：
  - 目标目录已存在同名文件；
  - 多个图片组重命名后目标路径相同；
  - 文件名不能为空、不能包含路径分隔符、必须保留图片扩展名。
  - 冲突行展示红色提示「已存在同名文件」及冲突图片缩略图；存在任意冲突时禁用「确认重命名」按钮。
- **确认校验**：点击确认时在插件侧再次计算冲突，避免预览期间外部文件变化导致误覆盖；只有全部无冲突才执行重命名。
- **重命名执行**：按组重命名基础图片及所有变体，使用 `overwrite: false` 防止覆盖已有文件；仅大小写变化时通过文件 `dev/ino` 判断是否指向同一文件，避免大小写不敏感文件系统误判冲突。
- **公共方法抽取**：新增 `ImagePreviewUtils`，导入预览与重命名预览共用图片预览 URI 生成逻辑。

- `src/utils/image-preview-utils.ts` (新建)
- `src/command/import-android-images.ts` (修改，复用图片预览工具)
