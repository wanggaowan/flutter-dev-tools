## 代码审查修复：安全、l10n 路径与图片生成流程

### 需求描述
根据代码审查结论，集中修复 WebView 注入与模板路径穿越、多项目（module）场景下的 l10n 路径解析、pubspec/图片引用生成的正确性问题，并补充纯函数单元测试。

### 实现细节
- 导入 Android 图片：内联 JSON 转义 `<` 并增加 CSP nonce；确认消息只合并 `targetName`/`importLast`/`overwrite`，来源文件与变体以插件侧数据为准；目标文件名校验为单个图片文件名，阻止路径穿越；按选中目录所在 module 计算图片目录。
- 文件模板：模板/目录/文件名称只允许单一路径片段，创建前校验目标路径必须位于基准目录内；导入或保存时过滤非法名称。
- l10n：新增 `FlutterModule.getL10nConfig()` 统一解析 `project-dir`/`arb-dir`/`template-arb-file`/`output-dir`（相对模块根目录，`output-dir` 缺省等于 `arb-dir`）；`getModule` 改为目录分隔符边界的最长前缀匹配；extract-l10n、translate-arb、translate-selection-to-arb、l10n-arb-watcher 改为按文档/模块使用绝对路径；翻译 arb 时跳过 `@@` 元数据并将非字符串值的 `return` 改为 `continue`；arb 监听器支持模板文件后续创建并复用 gen-l10n 终端。
- pubspec：`writePubspecAssetsOnly` 支持行内 `assets: []`、`flutter: # comment`，按缩进判断块结束，不再插入重复的 `assets:`/`flutter:` 键；只识别顶层 `flutter:`，不会误改 `dependencies.flutter` 依赖节点。
- 图片引用：方法名归一化所有非法字符，数字开头/Dart 关键字/纯非 ASCII 文件名使用 `img` 前缀或路径哈希；同一批次与重建流程按方法名去重；清理失效引用同时支持单双引号；写入前跳过编辑器中有未保存修改的文件；`dart format` 后不再 `doc.save()` 覆盖；图片创建事件按目录合并 300ms 处理，dispose 时清理所有定时器。
- 其它：l10n 定义/引用/装饰 provider 缓存改为按 module；ARB key 行统一解析并避免 key 前缀误匹配；图片预览按「基准目录 + 文件名」去重并跳过符号链接；`isImage` 改为带点的扩展名判断；翻译客户端按 AK/SK 缓存；gen-l10n 终端按目录复用。
- 新增 `src/test/utils.test.ts`，覆盖 `isImage`、`ImageVariantUtils.getBaseDir`、`extractL10nKeyFromCall`、`strCallRegex`、`getPlaceHolders`。
